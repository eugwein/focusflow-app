FocusFlow — Implementation Plan

An app that listens to classroom speech in real time, transcribes it, detects when something important is said (instructions, assignments, key concepts), and surfaces a simple, child-friendly summary only when it matters — minimizing distraction for users with attention difficulties.

System Instructions & Prompts

1. Live Transcription (WebSocket) System Instruction

The Gemini Live API requires a system instruction instructing the model to remain silent and function solely as a speech transcription engine.

You are a silent listener. Do not speak, do not respond, do not generate any audio output. Simply listen to the audio input.

2. Salience Detection Prompt (REST API)

Determines whether a chunk of text contains important information that should trigger an alert/checklist.

You are an attention assistant for a student who has difficulty staying focused in class. You will receive a chunk of what the teacher just said.

Determine if this contains SALIENT content the student needs to act on or remember. Also determine if the content contains MULTIPLE STEPS or a list of instructions.

SALIENT content includes:
- Instructions or assignments ("turn to page 5", "write your name", "first do X, then do Y, then do Z")
- Warnings or rules ("don't forget to...", "this will be on the test")
- Key new concepts being taught
- Schedule changes or deadlines
- Questions directed at the class

NOT salient: general explanation flowing continuously, casual chat, greetings, filler speech ("um", "so", "okay"), repetition of previously stated info.

Respond with JSON only:
{"is_salient": true, "category": "instruction", "has_multiple_steps": false, "step_count": 0, "confidence": 0.85}

3. Quick Alert Prompt (REST API)

Used when a single salient event or warning is detected.

You are a friendly helper for a young student (age 5-6) who has trouble paying attention. The teacher just said something important.

Write a SHORT, CLEAR summary:
- Use simple words a 5-6 year old can read
- 1-3 sentences maximum
- Start with a matching emoji:
  📝 for instructions    ⚠️ for warnings/rules
  💡 for key concepts    📅 for deadlines
  ❓ for questions
- Tell the student what to DO or REMEMBER
- Use direct language: "You need to..." not "The teacher said..."

Context of session so far: {session_summary}
Teacher just said: {recent_transcript}

4. Checklist Prompt (REST API)

Used when multi-step instructions are detected, rendering as an interactive checklist.

You are a friendly helper for a young student (age 5-6) who has trouble paying attention. The teacher just gave a set of instructions with multiple steps.

Create a NUMBERED CHECKLIST:
- List every step the teacher mentioned, in order
- Use simple words a 5-6 year old can read
- Keep each step to one short sentence
- Do NOT skip or combine steps — include ALL of them
- Uses direct language: "Open your book" not "The teacher said to open"

Respond with JSON only:
{"title": "short title", "steps": ["step 1", "step 2", "step 3"]}

Context of session so far: {session_summary}
Teacher just said: {recent_transcript}

Completed Implementations & Chronological Fixes

Step 1: Initial Setup

  • Initialized a distraction-free user interface matching the accessibility specs.
  • Created audio-capture.js using Web Audio API to capture raw microphone data at 48kHz, downsample it to 16kHz using an AudioWorkletNode (pcm-processor.js), and encode it to base64 PCM chunks.
  • Created chime.js to play short, warm tones on new summary alerts.
  • Configured local python test script (test_api.py) to verify the Gemini Live connection and transcript receiving logic.

Step 2: VAD Configuration Error Fix (1007)

  • Issue: WebSocket closed with code 1007 because of invalid automatic activity detection sensitivity values (START_SENSITIVITY_MEDIUM and END_SENSITIVITY_MEDIUM).
  • Fix: Updated VAD parameters in live-session.js to use supported API schema enums: START_SENSITIVITY_HIGH and END_SENSITIVITY_HIGH.

Step 3: API Key Security & Dual-Environment Sync

  • Issue: GitHub Push Protection blocked pushing to remote due to hardcoded API keys.
  • Fix: Replaced raw keys with placeholders (YOUR_API_KEY_HERE) in the version-controlled focusflow/ directory, while preserving the user's active key in the local playground/focusflow/ directory for development.

Step 4: Binary Message Parse Error Fix

  • Issue: Browser console threw SyntaxError: Unexpected token 'o', "[object Blob]" is not valid JSON. The Gemini Live API sends binary audio packets back to the client. Since JSON.parse expects a string, calling it on a binary Blob crashed the event loop, stopping transcripts from showing in the UI.
  • Fix: Rewrote _handleMessage(event) in live-session.js to detect Blob and ArrayBuffer objects, decode them to text, and catch JSON parse errors silently to ignore binary audio frames without crashing the transcription flow.
  • Improved Handshake Timing: Updated live-session.js to flag _setupDone = true only after the server acknowledges with setupComplete, ensuring no audio packets are sent before connection setup is finished.

Step 5: Summarizer Retry Logic

  • Issue: Summarizer failed during spikes in demand with API error 503 (Service Unavailable / Overloaded).
  • Fix: Added robust retry logic with exponential backoff (starting at 1s, doubling delay up to 3 retries) for transient HTTP errors (503, 429, 500, 504) and network disconnects inside summarizer.js's _callModel() helper.

Step 6: Favicon 404 Error Fix

  • Issue: Chrome console reported a 404 error fetching http://localhost:8080/favicon.ico.
  • Fix: Added an inline SVG data URL favicon tag (🎯) inside the <head> of index.html, immediately satisfying browser requests without checking in separate binary files.

Step 7: Settings Model Dropdown UI Upgrade

  • Issue: User requested model switching flexibility to avoid quota limits on older/newer models.
  • Fix: Added model selection dropdown to settings modal. Handled loading/saving model dynamically in localStorage (config.js, app.js), styled the dropdown (style.css), and updated summarizer.js to request dynamic models. Pushed changes to GitHub.

Step 8: Duplicate Checklist Numbering Fix

  • Issue: Item numbers rendered twice (e.g. 1. 1. Take out your worksheet.) when the Gemini API returned numbered JSON strings.
  • Fix: Added dynamic regex cleanup (/^\d+[\.\)\s-]+\s*/) in app.js checklist rendering to strip leading numbering prefixes before prepending the UI list numbers. Pushed changes to GitHub.

Vercel Deployment & Secure Edge Authorization Plan

To share the application with specific users while protecting it from the general public, we will configure Vercel Edge Middleware to perform HTTP Basic Authentication. This runs at Vercel's global edge network before any static HTML, CSS, or JS files are served to the user, making it highly secure and lightweight.

Edge Authorization File (middleware.js)

We introduced middleware.js at the root of the repository to intercept requests:

export const config = {
  // Protect all routes except static assets we might want to bypass (e.g., favicon)
  matcher: ['/((?!api|_next/static|_next/image|favicon.ico).*)'],
};

export function middleware(request) {
  const authorization = request.headers.get('authorization');
  
  if (authorization) {
    const base64 = authorization.split(' ')[1];
    const credentials = atob(base64);
    const [user, password] = credentials.split(':');
    
    // Read secure environment variables set in Vercel project settings
    const expectedUser = process.env.BASIC_AUTH_USER || 'admin';
    const expectedPassword = process.env.BASIC_AUTH_PASSWORD;
    
    if (expectedPassword && user === expectedUser && password === expectedPassword) {
      return; // Authorized: Allow the request to proceed to the static assets
    }
  }
  
  // Return HTTP 401 Unauthorized challenge to trigger browser login prompt
  return new Response('Authentication Required', {
    status: 401,
    headers: {
      'www-authenticate': 'Basic realm="FocusFlow Secure Area"',
    },
  });
}

Vercel Deployment Steps

Step 1: Push changes to GitHub
The middleware.js file has been pushed to the GitHub repository and is ready for Vercel's automatic import.

Step 2: Import Project on Vercel
Go to the Vercel dashboard, click Add New -> Project, and import the focusflow-app repository.

Step 3: Configure Environment Variables
In the Vercel project settings, configure the following Environment Variables:
1. BASIC_AUTH_USER (e.g., focususer)
2. BASIC_AUTH_PASSWORD (a secure password of choice)

Step 4: Deploy and Verify
Click Deploy. Access the deployment URL, verify the credential prompt triggers, and log in successfully to load the FocusFlow application.
